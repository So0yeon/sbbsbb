# 05 · 결정사항과 실패 기록

> 이 문서의 목적은 **같은 실수를 두 번 하지 않는 것**입니다.
> 아래 항목은 대부분 한 번 잘못 만들어 본 뒤에 나온 결론입니다.
> 시간이 없을 때 "그냥 이렇게 하면 안 되나?"라는 생각이 들면 여기부터 보세요.

## A. 구조에 관한 결정

### A1. 탐험 모드는 시대별 파일로 나눈다

```
js/engine/     엔진 — 모든 시대가 공유
  boot.js            부팅, 월드 전환, 타임라인
  state.js           ST 객체, questState, 저장/불러오기, 역사 가방
  ui.js              퀘스트 카드, 대화, 조사형, 완료 처리
  markers.js         3D 마커, 미니맵
  player.js          이동, 카메라, 조이스틱
  scene-helpers.js   지형·건물 빌더 (buildGround, jRoofHanok 등)
  minigames.js       미니게임 10형식 (8종 + 기본형 + blank)
  grader.js          답안 채점. 순수 함수, 의존성 0
  worlds-registry.js 모든 시대를 모아 WORLDS 테이블 구성
  constants.js

js/eras/       시대별 콘텐츠 — 서로 독립
  paleo.js  neolithic.js  bronze.js  samguk.js  unified-silla.js
  later.js  goryeo.js  joseon-early.js  joseon-late.js
  open-port.js  colonial.js  war.js
```

**왜**: 처음엔 `explore-app.js` 한 파일에 3,400줄이 몰려 있었습니다. 두 사람이 동시에 손대면 매번 충돌했습니다. 시대별로 쪼개고 나서 서로 다른 시대를 작업하면 충돌이 사라졌습니다.

**해커톤에서 특히 중요합니다.** 분업의 전제가 이 구조입니다.

### A2. 새 시대를 추가할 때 엔진을 고치지 않는다

새 시대는 이 세 가지만 하면 붙습니다.

1. `js/eras/<시대>.js` 새로 만들기
2. `worlds-registry.js`에 import 한 줄
3. `WORLDS`, `AREAS_BY_WORLD`, `AREA_BUILDERS_BY_WORLD`에 각각 한 줄

**엔진 파일을 건드려야 한다면 설계가 틀린 것입니다.** 필요한 기능이 없으면 범용 훅으로 추가하되, 기존 시대가 그 필드를 안 쓰면 동작이 그대로여야 합니다.

### A3. 지도 모드는 원본을 고치지 않고 얹는다

`map-app.js`, `map-data.js`는 그대로 두고 `atlas-*.js`가 위에 덮어씁니다.

```html
<script src="js/map-data.js"></script>      <!-- 원본 -->
<script src="js/atlas-geo.js"></script>     <!-- 얹기: 지도 데이터 -->
<script src="js/atlas-content.js"></script> <!-- 얹기: 항목 추가 -->
<script src="js/atlas-photos.js"></script>  <!-- 얹기: 사진 -->
<script src="js/map-app.js"></script>       <!-- 원본 -->
<script src="js/atlas-later.js"></script>   <!-- 얹기: 후삼국 보강 -->
<script src="js/atlas-dedupe.js"></script>  <!-- 얹기: 중복 정리 -->
<script src="js/atlas-integrate.js"></script>
```

**왜**: 두 팀이 각자 만든 것을 합칠 때, 원본을 고치면 양쪽 작업이 계속 충돌합니다. 얹는 방식이면 각자 계속 작업해도 됩니다.

### A4. 외부 CDN을 쓰지 않는다

three.js와 폰트를 `vendor/`에 넣습니다. 자세한 것은 [07-ASSETS.md](07-ASSETS.md).

**왜**: 개발 막바지에 인터넷을 끊고 시험해 보니 탐험 모드가 죽었습니다. 학교와 행사장 네트워크는 신뢰할 수 없습니다. **심사장에서 이게 터지면 아무것도 보여 줄 수 없습니다.**

### A5. 서버를 두지 않는다

백엔드도, 데이터베이스도, 로그인도 없습니다. 저장은 브라우저 `localStorage`뿐입니다.

**왜**: 학생 개인정보가 나갈 통로 자체를 만들지 않기 위해서입니다. 초등학생을 대상으로 하는 도구에서 이건 타협 대상이 아닙니다. 정적 파일이라 GitHub Pages로 바로 배포됩니다.

## B. 콘텐츠에 관한 결정

### B1. 사건을 나열하지 말고 생활의 변화로 연결한다

교육과정 문서가 명시하고 있습니다.

> 정치적 사건을 나열하기보다 생활 모습의 변화와 연결한다.
> 광복과 6·25 전쟁을 연대기적으로 나열하는 방식은 지양한다.

**실제로 이걸 어겼다가 고친 사례**: 조선 후기의 한산도·남한산성이 이순신·의병·진주대첩·병자호란으로만 채워져 있었습니다. 전란 일색이라 "그 시대 사람이 어떻게 살았나"가 없었습니다. 소금 굽기·판소리·보부상·서당을 넣어 채웠습니다.

### B2. 시대마다 지역 쏠림을 확인한다

한 지역에 퀘스트가 몰리면 나머지 지역이 텅 빕니다. 조선 후기가 **한양 15 · 화성 5**였습니다. 화성을 11개로 올려 균형을 맞췄습니다.

**점검 방법**: 시대별로 지역당 퀘스트 수를 세어 보고, 가장 많은 곳이 가장 적은 곳의 **2배를 넘으면** 손봅니다.

### B3. 활동 형식을 섞는다

한 시대에 선택형만 있으면 지루합니다. 네 가지를 섞으세요.

| 형식 | `kind` | 쓰임 |
|---|---|---|
| 역할 선택 | (없음) + `q:{choices, correct}` | 인물이 되어 판단. 정답 있음 |
| 열린 선택 | `choice` + `setup/prompt/choices/epilogue` | 정답 없음. 선택마다 다른 결과 |
| 조사형 | `inspect` + `hotspots` + `capstone` | 자료를 눌러 읽고 마무리 문제 |
| 미니게임 | `minigame` + `mini:{type}` | 손으로 조작 |

**미니게임이 0개인 시대가 있으면 손봐야 합니다.** 통일신라·발해가 그랬습니다.

### B4. 시대의 결을 지킨다

개항기 선택형은 **정답을 두지 않습니다.** 단발령 앞에서 상투를 자를지 말지에 정답이 없기 때문입니다. 새 퀘스트를 추가할 때도 그 시대가 이미 정한 결을 따르세요.

교육과정도 같은 방향입니다.

> 근대 문물을 단순히 "발전된 문명"으로 표현하지 않는다.
> 당시 사람들이 새로운 문물을 어떻게 받아들이고, 해석하고, 변형했는지를 탐구한다.

### B5. 설화와 사료가 어긋나면 둘 다 보여 준다

서동요 퀘스트는 이야기를 끝낸 뒤, 2009년 미륵사지 석탑에서 나온 기록이 『삼국유사』와 다르다는 점을 짚습니다. 고조선 경계는 학계 미확정이라 **점선**으로 표시합니다.

**이건 결함이 아니라 가르칠 거리입니다.** "학자마다 다르게 본다"를 보여 줄 수 있는 자리입니다.

### B6. 시대끼리 이어 준다

- 최치원이 골품제 벽에 막히는 이야기 → 후삼국에서 호족이 일어나는 배경
- 석가탑 쌓기 → 천이백 년 뒤 나온 무구정광대다라니경
- 양요와 척화비 → 강화도 조약
- 을사늑약 → 의병과 안중근 → 일제강점기

한 시대만 하고 끝내면 "외웠지만 그리지 못하는" 상태 그대로입니다.

## C. 반복해서 당한 함정

### C1. 배열 마지막 원소에는 쉼표가 없다

**이번에 세 번 당했습니다.** 퀘스트를 배열 끝에 추가할 때:

```js
  epilogue:'...' }      // ← 기존 마지막 원소. 쉼표 없음
{ id:'new-quest', ...   // ← 여기 붙이면 } { 가 되어 구문 오류
];
```

추가 전에 **직전 줄 끝에 쉼표부터** 넣으세요.

### C2. 닫는 중괄호를 세어라

`q:{ ... }`로 끝나는 퀘스트는 닫는 괄호가 **두 개**입니다.

```js
      no:'...' } },     // ← q 를 닫고, 퀘스트를 닫고, 쉼표
```

하나만 쓰면 퀘스트 객체가 열린 채로 남아 배열 끝에서 터집니다.

### C3. 콘솔 오류는 새 탭에서 판정하라

**이것 때문에 이번에 가장 오래 헤맸습니다.** 브라우저 콘솔 기록은 새로고침해도 지워지지 않습니다. 이미 고친 오류가 계속 보여서 없는 버그를 30분 넘게 쫓았습니다.

고친 뒤에는 **새 탭에서 열어** 판정하세요.

### C4. clipPath 안에 `<g>`를 넣지 마라

SVG 규격상 무시됩니다. **브라우저가 오류를 내지 않습니다.** 음영기복이 통째로 사라졌는데 화면을 직접 보기 전까지 몰랐습니다.

### C5. 좌표의 출처를 한 곳으로 못박아라

좌표가 두 파일에 나뉘어 있어서, 지도를 다시 만들 때마다 한쪽이 덮어써졌습니다. 지도 마커가 절반만 표시되는 증상이었습니다.

### C6. 눈대중 좌표로 한반도를 그리지 마라

40점짜리 손 좌표로는 아무리 다듬어도 한반도로 보이지 않습니다. Natural Earth 실측 데이터를 쓰세요 — 꾸러미의 `assets/countries-50m.json` (1:50m)입니다.

### C7. 퀘스트 좌표를 4단위 이상 띄워라

마커가 겹쳐서 하나를 누를 수 없게 됩니다. 새 퀘스트를 넣기 전에 그 지역의 기존 좌표를 확인하세요.

## D. 엔진 동작 중 기억해 둘 것

| 사실 | 의미 |
|---|---|
| `questState`는 월드별 `SAVE_KEY`에 저장 | 시대가 다르면 퀘스트 id가 같아도 서로 간섭하지 않음 |
| `contentId`는 선택 항목 | 없으면 역사 가방에 아무것도 안 담김 |
| `capstone`은 선택 항목 | 없으면 핫스팟을 다 보는 것으로 완료 |
| `mini.type`이 없으면 기본 미니게임 | `MINIGAME_STARTERS[undefined] \|\| startMinigame` |
| `stack`에 `visual`이 없으면 자동 생성 | **막집 기본값 금지.** `steps` 개수에 맞춘 도형을 그림 ([12-BUILD-RULES.md](12-BUILD-RULES.md) §3-3) |
| 역사 가방(`bag`)은 시대 공통 | `BAG_KEY = 'historyBagExplore_v1'` 하나 |

### 알려진 버그 (재현 시 고칠 것)

`collectContent(id)`가 `CONTENT`에서 항목을 못 찾으면 **영문 id를 그대로 화면에 표시합니다.**

```
🎒 "chongseongeo"을(를) 역사 가방에 담았어요
```

아이가 보는 화면입니다. 재생성할 때 `collectContent`에 방어 코드를 넣으세요 — 없는 항목이면 가방에 넣지도, 안내를 띄우지도 않게.

## E. 통합할 때의 원칙

### E1. 받아온 코드를 그대로 복사하지 않는다

다른 팀에서 받은 후삼국 코드는 **모듈 분리 이전 구조** 기준이었습니다. 통째로 넣었다면 분리가 되돌아가고 다른 시대가 로드되지 않았을 겁니다.

데이터는 그대로 두고 **구조만 현재 규약에 맞춰 옮기세요.** `index.html`도 교체가 아니라 필요한 부분만 병합합니다.

### E2. 중복 항목은 감추되 지우지 않는다

두 팀이 같은 유물을 다른 이름으로 넣은 곳이 46군데였습니다. `atlas-dedupe.js`의 스위치 하나로 고릅니다.

```js
const DUP_MODE = 'keep-both';   // keep-ours | keep-theirs | keep-both
```

원본을 고치지 않으므로 언제든 되돌릴 수 있고 충돌도 나지 않습니다.

**주의**: `keep-ours`로 바꾸면 탐험 퀘스트가 `theirs` 쪽 `contentId`를 참조하던 연결이 끊깁니다. 바꾸기 전에 탐험 모드를 확인하세요.

## 미니게임: 조작은 "그 기술/행위와 느낌이 이어지는" 것이어야 한다

**무엇**: "돌 갈기"(간석기 만들기) 미니게임이 두 번 리디자인됨.
1. 1차: 포인터 드래그(마우스/손가락으로 좌우로 밀기) — **제스처 인식이 불안정**해서 폐기.
2. 2차: 좌우 버튼을 그냥 번갈아 클릭 — 안정적이었지만 "너무 쉽고 단순해서 재미없다. 간석기 만드는 것과 상관도 없다"는 피드백으로 폐기.
3. 3차(현재): 좌우로 왕복하는 바늘이 무작위 구역을 지나는 순간에 맞춰 버튼을 누르는 **타이밍형**. 구역이 왼쪽/오른쪽 날을 번갈아 나타나고, 성공할수록 구역이 좁아지고 바늘이 빨라져 난이도가 상승. [`02-MINIGAMES.md`](02-MINIGAMES.md) §1 `grind` 참고.

**왜**: 미니게임 조작은 (a) 클릭/탭 기반이라 제스처 인식 오류가 없어야 하고 (b) 실제 그 행위(압력/타이밍/지속관리/순서기억 등)를 흉내내는 느낌이 있어야 재미와 의미가 함께 생김. 이미 검증된 10형식([`02-MINIGAMES.md`](02-MINIGAMES.md))이 이 기준을 통과했으므로, 새 미니게임이 필요할 때도 완전히 새로 만들기보다 이 중 서사적으로 가장 가까운 것을 재사용(다른 flavor로)하는 것을 우선 고려.

**적용**: 새 미니게임 설계 시 "이 조작이 실제 그 기술과 닮았는가?"를 항상 자문. 단순 랜덤 버튼 배정/좌우 교대 클릭 같은 임의 패턴은 피할 것.

## 3D 씬: 건물은 사람보다 명확히 커야 한다

**무엇**: 신석기 움집 등 일부 건물이 아바타(약 2.5 유닛)보다 낮게 만들어져 있었음. "건물이 사람보다도 작아서 현실성이 떨어진다"는 피드백으로 벽 높이·지붕 비율을 키우고 스케일 규칙을 명문화.

**왜**: 저폴리 3D에서 스케일 감각이 어긋나면 몰입이 크게 깨짐. 자세한 수치 규칙은 [`03-DESIGN-SYSTEM.md`](03-DESIGN-SYSTEM.md) §스케일 규칙.

**적용**: 새 건물/구조물을 만들 때마다 "지붕 꼭대기가 y=3.0 이상인가?"를 점검.

## 3D 씬: 빈 공간을 시대에 맞는 오브젝트로 채운다

**무엇**: "모든 시대의 공간이 좀 휑하다"는 피드백. 신석기 시대에 조개더미(패총)·통나무배·장작더미·저장 항아리·밭 울타리·바위·수풀 등을 추가해 밀도를 높임.

**왜**: 퀘스트 마커/집/농경지 등 핵심 오브젝트만 있으면 나머지 빈 땅이 허전해 보임. 그 시대를 상징하는 배경 소품(신석기=조개더미·간이 농기구, 청동기=고인돌·제사 도구, 전쟁=철조망·군용 잔해 등 시대성이 뚜렷한 것)을 흩뿌리면 적은 노력으로 몰입도가 크게 오름.

**적용**: 새 시대 맵을 만들 때 핵심 퀘스트/건물 배치 후, 그 시대를 상징하는 저비용 장식 오브젝트(바위/수풀/농기구/생활용품 등)를 §3-DESIGN-SYSTEM의 "배치 패턴"으로 흩뿌리는 단계를 항상 포함할 것. 시간이 없으면 최소한 바위+수풀 정도라도.

## 카메라: 드래그 오빗은 있는 게 낫다 (제거했다가 되돌림)

**무엇**: "화면 회전 안 되게 고정 가능?"이라는 요청으로 드래그 오빗(포인터로 카메라 좌우/상하 회전)을 제거하고 자동 추적만 남겼다가, 바로 다음 요청에서 "드래그락은 풀어줘"로 원복.

**왜**: 실제 의도는 "화면이 의도치 않게 빙글빙글 도는 게 산만하다"는 것이었지만, 원인은 드래그 오빗이 아니라 **이동 시 카메라가 캐릭터 방향으로 자동 추적**하는 동작(이건 유지하기로 확정, 아래 항목 참고)이었을 가능성이 큼. 드래그 오빗 자체는 사용자가 유지하고 싶어함.

**적용**: **드래그 오빗(포인터로 카메라 직접 회전)은 반드시 유지**할 것. 제거하지 말 것.

## 카메라: 이동 시 자동 추적은 유지 (논의했지만 안 바꾸기로 함)

**무엇**: 캐릭터가 이동하면 카메라 yaw가 이동 방향으로 자동으로 따라가는 동작. 어떤 사용자(플레이테스터)는 이게 산만하다며 "옆 키를 누르면 카메라 고정된 채 옆으로만 이동(스트레이프)"하는 방식을 선호한다고 피드백했지만, 실제 개발자(팀원)는 지금 방식이 좋다고 함.

**왜/결정**: 자동 추적 제거는 이동 감각 자체를 바꾸는 더 큰 변경이라, 드래그 오빗 락(위 항목)만으로 산만함이 상당 부분 줄어들 가능성이 있다고 보고 **일단 자동 추적은 그대로 유지하기로 결정**. 스트레이프 방식으로 바꾸는 건 보류.

**적용**: 자동 추적은 유지하되 **앞으로 갈 때만, 25° 넘게 어긋날 때만** 겁니다.
문자 그대로(이동 방향 뒤로 계속 돌린다) 만들면 `D` 를 누르고 있는 동안 아바타가 제자리를 도는
원을 그립니다 — 시험판에서 실제로 그랬습니다. 플레이테스터가 말한 "산만함"의 정체가 이것입니다.
정확한 규칙은 [12-BUILD-RULES.md](12-BUILD-RULES.md) §2-5.

## 조이스틱 좌우 반전 버그

**무엇**: 터치 조이스틱을 오른쪽으로 밀면 캐릭터가 왼쪽으로 이동하는 버그.

**왜**: 이동 로직이 키보드 `'a'`(왼쪽)를 `lx+=1`, `'d'`(오른쪽)를 `lx-=1`로 처리하는데, 조이스틱은 드래그 오프셋(`dx`, 오른쪽이 양수)을 그대로 `joy.x`에 넣어서 부호가 반대였음. `joy.x = -dx/max`로 수정.

**적용**: 부호는 [12-BUILD-RULES.md](12-BUILD-RULES.md) §2-2 의 표 하나로 통일했습니다
(화면 안쪽 `+`, 화면 오른쪽 `+`, 조이스틱도 같은 부호). 새 입력을 붙일 때 그 표와 맞추면 됩니다.

## 콘텐츠 소재 선정: 커리큘럼 문서가 기준

**무엇**: 각 시대에서 다루는 유물/인물/사건 소재는 임의로 정하지 않고 `curriculum.md` + `lesson1~3.md`(기존 커리큘럼 기획서)가 정한 범위를 따름.

**적용**: 새 퀘스트/콘텐츠를 추가할 때 커리큘럼 문서에서 해당 시대의 필수 소재를 먼저 확인. (이 스펙 문서 세트의 `content/*.md`는 이미 그 기준을 반영해 만들어진 기존 콘텐츠의 전문이므로, 그대로 옮기면 자동으로 커리큘럼을 따르는 것.)

## 어조: "그대/~하시오" 사극 톤은 explore 모드 스토리 텍스트, 콘텐츠 자체는 커리큘럼이 기준

**무엇**: 커리큘럼 문서(`curriculum.md`/`lesson*.md`)는 콘텐츠의 **소재 선정**(무엇을 다룰지)의 기준이고, 탐험 모드 특유의 사극풍 화법("그대는 ~이다", "~하라", "~보자")은 그대로 유지해야 하는 **톤**입니다. 커리큘럼 문서 자체는 다른 톤(설명체)으로 쓰여 있을 수 있는데, 그걸 그대로 게임 텍스트에 복사하면 안 됨 — 소재만 가져오고 톤은 기존 퀘스트 텍스트(`content/*.md`)를 참고해 사극풍으로 다시 씀.

**적용**: `content/*.md`에 이미 담긴 기존 퀘스트 텍스트는 이 톤이 적용된 최종본이므로 그대로 재현하면 되고, 새로 콘텐츠를 추가할 때만 이 규칙을 신경 쓰면 됨.
