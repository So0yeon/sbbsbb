# 03 · 디자인 시스템

> 두 모드가 **하나의 도구로 보여야 합니다.** 지도 모드는 종이 지도의 차분함,
> 탐험 모드는 저폴리의 부드러움 — 서로 달라 보이되 같은 색 감각을 씁니다.
>
> 초등학생이 씁니다. **화려함보다 알아보기 쉬움이 먼저입니다.**

---

## 1. 색

### 기본

```css
--bg:#F7F7F5;          /* 종이 같은 배경. 순백이 아닙니다 */
--card:#FFFFFF;
--text:#191919;        /* 검정이 아닌 짙은 회색 */
--text2:#777777;
--text3:#A3A3A0;
--border:#EAEAEA;
--border-strong:#DDDDDA;
--accent:#6E9B94;      /* 청록. 이 도구의 얼굴색 */
--accent-soft:rgba(110,155,148,.12);
```

**순백(`#FFF`)과 순흑(`#000`)을 배경·본문에 쓰지 마세요.** 화면을 오래 보는 아이의 눈이 피로해집니다.

### 지도

```css
--sea:#E8E9E4;         /* 바다가 파랗지 않습니다 */
--land:#FCFCFA;
--land-far:#F1F1EC;    /* 주변국 — 한 단계 물러나 보이게 */
--coast:#D4D4CC;
```

바다를 회녹색으로 둔 것은 **나라 영역의 색이 주인공이어야 하기 때문**입니다. 바다가 파랗면 시대별 영역 색이 묻힙니다.

### 분류 여섯 가지

| 변수 | 색 | 분류 |
|---|---|---|
| `--c-relic` | `#7B6A55` | 유물·유적 |
| `--c-person` | `#3F6B8C` | 인물 |
| `--c-culture` | `#3E8A78` | 문화 |
| `--c-event` | `#A8534F` | 사건 |
| `--c-exchange` | `#7C6BA8` | 교류 |
| `--c-life` | `#8A7B4E` | 생활문화 |

전부 **채도를 낮춘 색**입니다. 원색을 쓰면 지도가 어지러워집니다.

### 시대 색 (`accent`)

시대마다 하나씩 갖습니다. 흙·풀·돌에서 온 색으로 고르세요.

```
구석기 #B08968   신석기 #BFA06E   청동기 #A98467
삼국   #4E7F6A   …
```

**시대가 흐를수록 색이 조금씩 차가워지게** 배열하면 타임라인이 시간의 흐름처럼 읽힙니다.

## 2. 글자

```css
--font:'Pretendard Variable','Pretendard',-apple-system,…
```

Pretendard를 `vendor/font/`에 동봉합니다. ([07-ASSETS.md](07-ASSETS.md))

- 본문은 **한글 가독성**이 최우선입니다
- 아이가 읽을 본문에 **8pt 미만을 쓰지 마세요**
- 숫자와 연도는 본문과 같은 굵기로. 강조하면 연표 암기처럼 보입니다

### 문체

문서 전체에 걸친 규칙입니다.

| 대상 | 문체 | 예 |
|---|---|---|
| 지도 모드 설명 | **~해요체** | "돌을 깨뜨려 도구를 만들었어요." |
| 탐험 모드 서술 | **~다체** (고풍) | "그대는 시간의 틈에 휩쓸려 …" |
| 탐험 모드 선택지 | **1인칭 다짐** | "당과 맞서 싸워 이 땅에서 몰아내자!" |
| 조사형 `note` | **~해요체** | "1978년 이곳에서 주먹도끼가 …" |

**섞지 마세요.** 지도 모드에서 "~하였다"가 나오면 갑자기 교과서가 되고, 탐험 모드에서 "~해요"가 나오면 몰입이 깨집니다.

## 3. 모양

```css
--r-sm:10px;  --r-md:14px;  --r-lg:20px;  --r-xl:26px;
--sh-1: 0 1px 2px rgba(25,25,25,.04), 0 4px 14px rgba(25,25,25,.06);
--sh-2: 0 2px 6px rgba(25,25,25,.05), 0 12px 34px rgba(25,25,25,.10);
--ease: cubic-bezier(.22,.8,.36,1);
--t-fast:180ms;  --t:280ms;  --t-slow:400ms;
```

- 모서리는 **넉넉하게** 둥글립니다. 아이용 도구의 인상을 만듭니다
- 그림자는 **두 겹**입니다. 가까운 것과 먼 것을 겹쳐야 떠 있어 보입니다
- 전환은 `--ease` 하나로 통일합니다. 튀는 곡선을 섞지 마세요

### 터치 목표

**최소 44×44px.** 태블릿에서 아이 손가락으로 눌립니다. 지도 마커도 보이는 원보다 **터치 영역을 크게** 잡으세요.

## 4. 3D (탐험 모드)

### 스타일

**저폴리(low-poly) · 플랫셰이딩.** 사실적인 재현을 하지 않습니다.

```js
new THREE.MeshStandardMaterial({ color: col, flatShading: true })
```

이유는 셋입니다. 만들기 빠르고, 태블릿에서 가볍고, **"이건 옛날을 그대로 찍은 게 아니라 그린 것"** 이라는 신호를 줍니다. 고증이 확실하지 않은 부분을 사실처럼 보여 주지 않기 위해서입니다.

### 조명

```js
scene.fog = new THREE.Fog(bg, 38, 92);
scene.add(new THREE.HemisphereLight('#EAF2EF', '#B9A98A', 1.15));

const sun  = new THREE.DirectionalLight('#FFF3DD', 1.3);
sun.position.set(28, 42, 14);

const fill = new THREE.DirectionalLight('#CFE3FF', 0.5);
fill.position.set(-22, 20, -12);
```

- **반구광이 주력**입니다. 위는 옅은 청록, 아래는 흙빛
- 해는 **따뜻한 크림색**, 채움광은 **차가운 하늘색** — 이 대비가 저폴리 면을 살립니다
- 안개를 배경색과 같게 두면 **먼 곳이 지평선으로 자연스럽게 사라집니다**
- **그림자를 켜지 마세요.** 태블릿에서 프레임이 떨어지고, 저폴리에서는 있으나 마나입니다

### 렌더러

```js
renderer.setPixelRatio(Math.min(window.devicePixelRatio || 1, 2));
renderer.outputColorSpace = THREE.SRGBColorSpace;
```

픽셀 비율을 **2로 잘라야** 고해상도 태블릿에서 느려지지 않습니다.

### 크기 감각

캐릭터 키를 **약 2 단위**로 잡고 나머지를 거기 맞춥니다.

| 대상 | 대략 |
|---|---|
| 캐릭터 | 높이 2 |
| 초가·기와집 | 폭 3~5, 높이 2~3 |
| 궁궐 | 폭 5~6, 높이 3~4 |
| 성문 | 높이 4~5 |
| 석탑 | 높이 3~4 |
| 지역 반경(`bound`) | 36~72 |

**건물을 실제 비례로 만들지 마세요.** 궁궐을 실제 비례로 하면 화면에서 캐릭터가 개미가 됩니다. "조금 작은 장난감 마을"이 맞습니다.

### 배경색

지역마다 `bg`를 다르게 둡니다. **시대의 인상을 색 하나로 전합니다.**

```
한산도 #B9D6D9 (바다)   남한산성 #C7CBB8 (겨울 산)
철원   #D9DEE0 (분지)   송악     #DCE5DF (강)
```

## 5. 에셋 만들 때

### 3D 모델(GLB)

`assets/`에 넣고 필요한 시대에서만 부릅니다. **없어도 앱이 돌아가야 합니다** — 기본 도형으로 대체되게 하세요.

실제로 쓰는 두 개(자격루 12MB · 청동 창 3.7MB)가 15.7MB입니다. 시간이 모자라면 여기부터 버립니다.
**나머지 7점은 앱에서 부르지 않습니다.** 출처·라이선스도 미확인이라 사용 전 확인이 필요합니다.

### 사진

`webp`로 변환합니다. **가로 1200px을 넘기지 마세요.** 상세 시트에서 그보다 크게 보일 일이 없습니다.

### 아이콘

**이모지를 씁니다.** SVG 아이콘 세트를 만들지 마세요. 시간이 없고, 이모지가 아이에게 더 잘 읽힙니다.

퀘스트 아이콘은 **내용과 맞춘 것**으로 고르세요. `📌` 같은 범용 기호를 남발하면 목록에서 구분이 안 됩니다.

## 2. 탐험 모드 공용 컴포넌트 클래스 — 재사용 필수

퀘스트 모달(`.quest-card`)/이벤트 시트(`.event-card`)/미니맵 모달(`.exmini-card`)이 전부 공유하는 클래스 세트입니다. **새 퀘스트 UI를 만들 때 절대 새 카드 스타일을 만들지 말고 이 클래스들을 그대로 쓰세요**:

- `.q-head` (아이콘+태그+제목 가로 배치) → `.q-mi`(48×48 원형 배경+아이콘) + `.q-tag`(작은 라벨) + `.q-title`
- `.q-story` (배경 스토리, 양피지색 박스)
- `.q-reveal` (점선 테두리 "이제 어떻게 할까?" 버튼 — 누르면 `.q-quiz-wrap`이 펼쳐짐)
- `.q-choices` > `.q-choice`(번호 원+텍스트) — 정답 클릭 시 `.correct`, 오답 시 일시적으로 `.wrong`
- `.q-blank-wrap`(입력창+확인 버튼) — 빈칸 채우기 퀴즈용, `.q-blank-input.wrong`/`:disabled`(정답 시)
- `.q-fb.on.ok`/`.q-fb.on.no`/`.q-fb.on.neutral` — 피드백 박스
- `.q-next.on` — 하단 pill 버튼("탐험 계속하기"/"시작하기 →"/"다시 도전하기" 등 상황별 텍스트만 바꿔 재사용)
- 모달 여닫힘 공통 패턴: `.on` 클래스 토글로 opacity/visibility/pointer-events 전환 + 카드 자체는 `translateY(10px) scale(.97)` → `none`으로 살짝 떠오르는 등장 애니메이션(`var(--t)`)

## 3. 3D 저폴리 스타일 컨벤션 (scene-helpers.js)

### 원칙

- **저폴리, flat shading 위주**: `MeshStandardMaterial({color, flatShading:true})`가 기본. 복잡한 텍스처 대신 색 블록으로 구성.
- **기본 지오메트리만 사용**: `BoxGeometry`/`CylinderGeometry`/`ConeGeometry`/`SphereGeometry`/`TorusGeometry`/`Dodecahedron`/`Tetrahedron`/`Icosahedron`/`Octahedron`/`PlaneGeometry` — 커스텀 지오메트리나 외부 모델 로더 없이 이 조합만으로 모든 오브젝트를 조립합니다(단 GLB 3D 모델을 실제로 쓰는 경우도 소수 있음 — `assets/*.glb`, 필수는 아님).
- **파츠 조합 패턴**: 큰 물체는 `THREE.Group`에 여러 메시를 자식으로 추가하는 방식(예: 초가집 = 벽 박스 + 지붕 구+문 박스). 새 오브젝트를 만들 때 이 패턴을 따르세요.

### 재사용 가능한 공용 빌더 (scene-helpers.js, 그대로 재사용)

| 함수 | 용도 |

| `buildGround()` | 110×110 평면 바닥 (색 `#E9E4D3`) |
| `buildWater()` | 강/바다 평면 (30×120, 청록 반투명 `#8FC1C4`) |

| `scatterHouses(n,xr,zr,exclude,{strawRatio,avoid})` | 초가/기와 섞어서 마을 산포 (기본 초가 55%) |

### ⚠️ 스케일 규칙 (실제로 겪은 버그, 반드시 지킬 것)

플레이어 아바타는 발밑 y=0, 머리 꼭대기 **y≈2.5**입니다([`12-BUILD-RULES.md`](12-BUILD-RULES.md) §2-1). **모든 건물/구조물은 이보다 명확히 커야 합니다** — 과거 초가집 등이 아바타보다 작게 만들어져 있던 버그가 실제로 있었고("건물이 사람보다 작다"는 피드백으로 수정됨, [`05-DECISIONS.md`](05-DECISIONS.md)).

- **작은 오두막/움집류**: 벽 높이 1.2~1.6, 지붕 정점까지 총 높이 최소 3.0 이상 (아바타의 약 1.3~1.8배)
- **일반 초가/기와집**: 총 높이 3~4.5
- **성문/관문/큰 건물**: 총 높이 4~6+
- 검증 방법: "지붕 꼭대기 y좌표가 3.0 미만이면 다시 키울 것" — 새 오브젝트를 만들 때마다 이 숫자로 자가 점검하세요.

### 배치(겹침 방지) 패턴

기존 코드가 쓰는 관례: 새 장식 오브젝트를 흩뿌릴 때 퀘스트 마커(`ST.QUESTS[].pos`)와 이미 배치한 다른 건물 목록에서 일정 반경(보통 3.5~7) 안이면 스킵하는 방식으로 겹침을 방지합니다. **제외 목록에 그 지역의 NPC 좌표와 `spawn` 도 반드시 넣으세요** — 빠뜨리면 도착하자마자 나무 속에 서 있습니다([12-BUILD-RULES.md](12-BUILD-RULES.md) §4). 이미 `buildTreesNeo`/`scatterHouses`류 함수가 이 패턴으로 구현돼 있으니 새 산포 함수를 만들 때 그대로 베끼면 됩니다(랜덤 좌표 뽑기 → 제외 조건 체크 → 통과하면 배치, 정해진 개수 찰 때까지 또는 시도 횟수 한도까지 반복).
