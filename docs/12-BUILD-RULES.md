## 1. 퀘스트 분류(`cat`)는 지도 모드에서 가져온다

`docs/content/*.md` 의 퀘스트에는 `cat` 이 적혀 있지 않습니다. **적지 마세요.** 대신 이렇게 정합니다.
`cat` 은 **6종뿐**입니다 — `relic` `person` `culture` `event` `exchange` `life`.
전투는 `event` + `war:true` 플래그입니다(`01-ARCHITECTURE` 가 적었던 7종 표기는 오기).

1. `contentId` 가 있으면 → `CONTENT` 에서 그 항목을 찾아 **`cat` 배열의 첫 번째** 값을 씁니다.
2. `contentId` 가 없거나 `CONTENT` 에 없으면 → 아이콘 이모지로 정합니다.
   `⚔️🗡️🏹🛡️💥🔥🚩`→`event` · `👑🤴👘`→`person` · `🏺💎🔔📜🪙`→`relic`
   `🎨🖼️🎵🎭📖`→`culture` · `🍚🍜🧺🏠♨️`→`life`
3. 그래도 못 정하면 `kind` 로: `inspect`→`relic` · `choice`·`minigame`→`life` · 나머지 `event`.

**왜**: 이렇게 하면 같은 유물이 두 모드에서 같은 색으로 나옵니다. 손으로 정하면 반드시 어긋납니다.

## 2. 이동 · 카메라 · 입력

다른 문서가 "§01-ARCHITECTURE 7절"이라고 가리키는 내용이 여기 있습니다.

### 2-1. 아바타

발밑 `y=0`, 머리 꼭대기 **`y≈2.5`**. 아바타는 **`+z` 를 바라보게** 만듭니다
(그래야 `rotation.y = atan2(dx, dz)` 로 진행 방향을 향합니다).
코나 상투처럼 **앞뒤를 구분해 주는 돌기**를 하나 붙이세요 — 없으면 어느 쪽을 보는지 모릅니다.

### 2-2. 입력 부호 — 이 표가 유일한 출처

| 입력 | 뜻 |
|---|---|
| `fwd = +1` | 화면 안쪽(카메라에서 멀어지는 쪽) — `W` `↑` |
| `fwd = -1` | 화면 앞쪽(카메라 쪽) — `S` `↓` |
| `strafe = +1` | 화면 오른쪽 — `D` `→` |
| `strafe = -1` | 화면 왼쪽 — `A` `←` |
| 조이스틱 | `joy.z` 위가 `+`, `joy.x` 오른쪽이 `+` (같은 부호를 씁니다) |

두 축을 합칠 때 길이가 1을 넘으면 정규화합니다(대각선이 빨라지지 않게).

### 2-3. 키는 `e.key` 가 아니라 `e.code` 로 받는다

**한글 입력 상태에서 `W A S D` 의 `e.key` 는 `ㅈ ㅁ ㄴ ㅇ` 입니다.**
`e.key === 'w'` 로 만들면 한글 자판을 쓰는 교실에서 이동이 통째로 죽습니다.

- `e.code`(`KeyW` `ArrowUp` …)를 먼저 봅니다.
- `e.code` 가 비어 오는 환경을 위해 `ㅈ ㅁ ㄴ ㅇ` 과 `w a s d` 표도 함께 둡니다.
- 창이 포커스를 잃으면(`blur`, `visibilitychange`) **누른 키를 모두 비웁니다.** 안 그러면 계속 걷습니다.
- 방향키·스페이스는 `preventDefault()` — 안 하면 페이지가 같이 스크롤됩니다.

### 2-4. 카메라 축과 이동 방향

카메라는 아바타를 중심으로 `camYaw` 만큼 돌아간 자리에 있습니다.

```
카메라 위치 = 아바타 + ( sin(camYaw), 높이, cos(camYaw) ) × 거리
화면 안쪽 f = ( -sin(camYaw), -cos(camYaw) )
화면 오른쪽 r = (  cos(camYaw), -sin(camYaw) )
이동 방향 = f × fwd + r × strafe        (정규화 후 속도 ≈ 9 / 초)
아바타 각도 = atan2(방향.x, 방향.z)
```

### 2-5. 카메라 자동 추적 — **앞으로 갈 때만, 25° 넘게 어긋날 때만**

`05-DECISIONS` 의 "자동 추적 유지"를 문자 그대로(이동 방향 뒤로 계속 돌린다) 만들면
**`D` 를 누르고 있는 동안 아바타가 제자리를 도는 원을 그립니다.** 카메라가 돌면 화면 기준 축도
같이 돌아 입력 방향이 계속 밀리기 때문입니다. 그래서 이렇게 제한합니다.

- `fwd > 0.1` 일 때만 추적한다 (뒷걸음·옆걸음에서는 카메라를 고정한다)
- 목표 각도와의 차이가 **25°** 를 넘는 만큼만 천천히 따라간다
- **드래그 중에는 추적하지 않는다** (드래그 오빗은 반드시 유지 — `05-DECISIONS` 참고)

이렇게 하면 `W` 는 곧게, `W+D` 는 부드럽게 따라오다 멈추고, `D` 만 누르면
카메라는 그대로인 채 아바타만 오른쪽을 보고 옆으로 갑니다.

### 2-6. 조이스틱은 손가락 기기에서만 띄운다

`01-ARCHITECTURE` 의 DOM 뼈대는 `#exJoy` 를 `aria-hidden="true"` 로 시작합니다.
`(pointer: coarse)` 이거나 첫 `touchstart` 가 오면 `false` 로 바꿔 주세요.
**이걸 놓치면 태블릿 교실에서 아이가 한 걸음도 움직이지 못합니다.**
작은 화면에서는 하단 타임라인과 겹치지 않게 조이스틱을 위로 올립니다(`bottom: 78px` 안팎).

## 3. 타이밍 미니게임은 **누르는 순간**에 판정한다

`02-MINIGAMES` 는 성공 조건만 정하고 언제 판정하는지를 적지 않았습니다.
버튼의 `click` 으로 만들면 판정이 **손을 뗄 때** 일어납니다. 누르고 떼는 사이가 보통
80~150ms 인데, 바늘이 빠를 때 이건 화면의 10~20% 입니다. 시험판에서 첫 플레이어가
곧바로 "제대로 눌렀는데 진다"고 했습니다.

- 판정은 **`pointerdown`**. 뒤따라오는 `click` 은 700ms 안이면 무시합니다
  (키보드 `Enter`·스페이스로 누른 `click` 은 살려 둡니다).
- **디바운스로 막지 마세요.** 250ms 디바운스를 뒀더니 빠른 연타가 통째로 먹혔습니다.
- 화면은 코드보다 한두 프레임 뒤에 그려집니다. **아이가 "본" 자리**(2프레임 전 위치)도
  함께 명중으로 쳐 줍니다.
- `knap` 처럼 놓는 순간을 재는 것은 `pointerup` 판정이 맞습니다 — 지연 보정만 똑같이 넣습니다.

### 3-1. 바늘형 난이도 (시험판에서 맞춘 값)

| 종류 | 구간 폭 (시작 → 최소) | 속도 (시작 → 최대) | 성공 |
|---|---|---|---|
| `grind` | 16 % → 7.5 % | .95 → 2.0 | 10번 중 6번 |
| `lift` | 18 % → 9.5 % | .88 → 1.9 | 8번 중 5번 |
| 기본형 | 23 % → 14 % | .80 → 1.7 | 3번 중 2번 |
| `knap` | 20 % → 8 % | 게이지가 0.75초에 100 % | 6번 중 4번 |

명중할 때마다 구간이 3 % 안팎 좁아지고 속도가 .1 안팎 빨라집니다.
**버튼 크기는 난이도 조절에 쓰지 마세요** — 터치 목표 44×44 는 타협 대상이 아닙니다
(`03-DESIGN-SYSTEM`). 난이도는 구간 폭과 속도로만 올립니다.

### 3-2. `blank` — 10번째 형식

`02-MINIGAMES` 의 8종·기본형 말고 **빈칸 채우기**가 콘텐츠 문서에 **16번** 나옵니다.
`06-later` 와 `10-open-port` 를 뺀 **10개 시대 전부**입니다 —
(`미니게임 종류: blank` 11번 = `01` `02` `03` 각 1 · `11-colonial` 6 · `12-war` 2,
`형식: 빈칸 채우기 문제` 5번 = `04` `05` `07` `08` `09` 각 1)

**콘텐츠 문서에서 가장 많이 쓰이는 형식입니다**(다음이 `stack` 12번). 반드시 만드세요.

- 표시: 문장 안의 `____` + 입력칸 + 확인 버튼
- 판정: 공백·가운뎃점·문장부호를 지우고 비교. 맞으면 `ok`, 틀리면 `no` 를 보여 주고 다시 시도
- 콘텐츠 문서 표기: 역할 선택이면 `**형식**: 빈칸 채우기 문제`, 조사형 마무리 문제면
  `**미니게임 종류**: \`blank\`` — 둘 다 `**정답**: <낱말>` 로 답을 적습니다

### 3-3. `stack` 의 `visual` 이 없을 때

콘텐츠 문서에는 `visual` SVG 가 하나도 없습니다. **막집 그림을 기본값으로 두지 마세요.**
`steps` 개수에 맞춰 아래에서 위로 쌓이는 단순한 도형을 그려 주는 편이 안전합니다.

## 4. 3D 배치 — 겹침 방지

산포 함수(`scatterTreesArea` `scatterHouses` 등)의 제외 목록에 **셋을 모두** 넣습니다.

1. 그 지역 퀘스트 좌표 (`ST.QUESTS[].pos`)
2. 그 지역 NPC 좌표
3. **그 지역 `spawn`** ← 이게 빠져서 시험판에서 도착하자마자 나무 속에 서 있었습니다

나무는 3.5 이상, 집은 6.5 이상 띄웁니다.

### 4-1. 산은 `bound` 바깥에 둔다

초기에는 배경 산을 반지름 37~44 에 고정해 두었는데, 지역 `bound` 는 36~72 입니다.
**`bound` 가 44보다 크면 걸어서 산을 뚫고 지나갑니다.** 산 반지름을 `bound × 1.02` 부터로 잡으세요.

### 4-2. 지역 값

각 콘텐츠 문서 `## 지역` 절의 표에 `bg` `spawn` `bound` `loading` 을 적어 두었습니다.
`bound` 는 그 지역에서 가장 먼 마커 거리 + 8 입니다. 퀘스트를 옮기다 좌표를 바꾸면 다시 계산하세요.

## 5. 지도 모드 지도

### 5-1. 영역 클립은 두 벌

- `kr:1` → 한반도(제주·섬 포함)로 자른다
- `kr` 없음 → **대륙(주변국 포함) 육지로 자른다.** 자르지 않으면 고구려 영역이 동해로 번집니다

`clipPath` 안에는 `<g>` 를 넣지 마세요(규격상 무시되고 오류도 안 납니다 — `05-DECISIONS` C4).

### 5-2. 라벨은 겹치면 뺀다

나라 이름과 도읍 이름이 **먼저** 자리를 잡고, 항목 라벨은 위 → 아래 → 더 위 순으로
자리를 옮겨 보고 그래도 겹치면 **라벨만** 뺍니다. 점은 남겨 두어 누를 수 있게 합니다.

### 5-3. 사진은 있는 것만

`assets/photos/CREDITS.md` 의 파일 이름이 곧 학습 항목 id 입니다 —
사진 68장 = 학습 항목에 붙는 46파일(→ **항목 41개**, `-2` 변형 5개) + 아직 못 붙인 `hb_*` 22장.
**학습 항목 146개 중 105개는 사진이 없습니다.**
**표에서 목록을 만들어 두고, 목록에 없으면 사진 칸 자체를 그리지 않습니다.**
`onerror` 로 숨기면 콘솔에 404 가 쌓입니다. 저작자와 라이선스는 사진마다 그대로 표시합니다.

## 6. 콘텐츠 문서 → 시대 파일 (12개 전부 만든다)

`docs/content/*.md` 는 **기계적으로 옮길 수 있을 만큼 규칙적입니다.** 손으로 옮기지 말고
변환 규칙을 한 번 만들어 12개 시대에 그대로 돌리세요. 시험판에서는 이 방식으로
세 시대(퀘스트 102개)를 한 번에 옮겼고, 나머지 아홉도 같은 형식입니다.

### 6-1. 읽는 규칙

| 문서에 있는 것 | 되는 것 |
|---|---|
| `### <이모지> <제목>` | `icon`, `title` |
| `` `id` · **종류** · 지역 `area` · 좌표 `{x,z}` · 학습 항목 `contentId` `` | 나머지 필드. **종류**가 `kind` (역할 선택→없음 · 열린 선택→`choice` · 조사형→`inspect` · 미니게임→`minigame` · 수집형→`find`) |
| `**상황**` 뒤 인용문 / `**요약**: …` | `story` (열린 선택은 `setup`) |
| `**묻는 말**: …` + `선택지` 목록 + `정답: N번` | `q:{text, choices, correct}`. **묻는 말이 두 번 이상이면 `stages` 로 이어 붙입니다** |
| `**맞았을 때**` / `**틀렸을 때**` 인용문 | `q.ok` / `q.no` |
| `- **라벨** — 설명` (조사형) | `hotspots[]` |
| `**마무리 문제**: …` | `capstone` |
| `**마무리**` 인용문 | `epilogue` |
| `**미니게임 종류**: \`type\`` · `**단계**` · `**조작 안내**` + `- 아이콘 라벨 → 왼쪽/오른쪽` | `mini.type` · `mini.steps` · `mini.intro` · `mini.items` |
| `**실패했을 때**: …` | `mini.retry` |
| `**찾을 것**` 목록 · `**다 모았을 때**: …` | `find` 퀘스트들과 `doneMsg` |
| 관문 표 | `GATES_*` → `kind:'gate'` 로 합침 |
| 길에서 만나는 사람들 | `NPCS_*` |
| 지역 지형 배치 표 | 지역 빌더 함수 (표의 호출을 순서대로) |

**옮길 때 하지 말 것**: 텍스트를 다듬는 것. 오타처럼 보여도 그대로 옮기고, 진짜 오타는
콘텐츠 문서 쪽을 고칩니다(그래야 두 번 고치지 않습니다).

### 6-2. 시대마다 손으로 써야 하는 것

배치표의 **지역 빌더**는 그대로 옮겨지지만, 그 표가 부르는 **시대 전용 소품**
(`buildBunker` `buildJangsi` `buildObservatoryTower` 같은 것)은 표가 비어 있어 새로 써야 합니다.
시대당 2~5개, 6·25만 17개입니다. 공용 빌더를 조합하고, **지붕 꼭대기가 `y=3` 이상**인지 확인하세요.

### 6-3. 순서

1. 변환 규칙을 만들고 **한 시대**로 검증 (퀘스트 하나 완료까지 직접 플레이)
2. 나머지 11개 시대를 같은 규칙으로 변환
3. 시대별 전용 소품을 채운다 — **여기가 진짜 시간이 드는 곳**
4. `worlds-registry.js` 에 12개를 등록 (한 사람이 마지막에 몰아서)

시간이 모자라면 **시대를 빼지 말고 그 시대의 전용 소품을 줄이세요.** 공용 빌더만으로도
