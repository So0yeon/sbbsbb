# 08 · 만드는 차례와 우선순위

> 시작 시각부터 무엇을 어떤 순서로 만들지 적어 둔 문서입니다.
> **순서가 곧 속도입니다.** 의존 관계를 어기면 되돌아가서 다시 만들어야 합니다.

---

## 0. 시작 5분 안에 할 일

**`vendor/` · `assets/` · 사진 68장 · `countries-50m.json` 은 이미 꾸러미에 들어 있습니다.**
대회 시작 후 내려받아야 할 것은 하나뿐입니다. 자세한 것은 [07-ASSETS.md](07-ASSETS.md).

```
1. 누락 webp 14장 수집   ← 백그라운드. 없어도 화면은 성립합니다
```

그리고 저장소를 만들고 첫 커밋을 남기세요. 시작 시각 이후의 이력이 남아야 합니다.

## 1. 시간 배분

8~14시간 기준입니다. **12개 시대를 전부 만듭니다.**

한 번 시험 삼아 만들어 보고 바뀐 판단입니다. 퀘스트 243개를 손으로 옮기면 시대당 30~45분이
걸리지만, `docs/content/*.md` 는 **기계적으로 옮길 수 있을 만큼 규칙적**입니다.
변환 규칙을 한 번 만들어 12개에 그대로 돌리면 콘텐츠 이전 자체는 순식간입니다
(시험판에서 세 시대·퀘스트 102개를 한 번에 옮겼습니다).
진짜 시간이 드는 곳은 **시대별 전용 3D 소품**입니다. 자세한 절차는
[12-BUILD-RULES.md](12-BUILD-RULES.md) §6.

| 구간 | 시간 | 내용 | 없으면 |
|---|---|---|---|
| 1단계 | 1.5h | 엔진 뼈대 + 껍데기 | 아무것도 안 됨 |
| 2단계 | 1.5h | 미니게임 10형식 + `grader.js` | 시대가 밋밋해짐 |
| 3단계 | 1h | **변환 규칙 만들고 한 시대로 검증** | 12개를 손으로 옮기게 됨 |
| 4단계 | 1h | 나머지 11개 시대 변환 + 레지스트리 등록 | 시대가 3개뿐 |
| 5단계 | 3~5h | 시대별 전용 소품 채우기 (시대당 2~5개, 6·25는 17개) | 지형이 휑함 |
| 6단계 | 2h | 지도 모드 (2D 지도) + 학습 항목 신규 20개 | 반쪽짜리 |
| 7단계 | 1h | 인쇄(학습지·기록지) · 통합·검증·배포 | 심사장에서 터짐 |

### 우선순위 컷라인

**반드시**: 엔진 + 미니게임 10형식 + **탐험 12시대 전부** + 지도 모드 기본
**되면**: 시대별 전용 소품 전부 + 학습지·기록지 인쇄 + 사진 68장
**시간 남으면**: GLB 3D 모델, 교사용 편집

**시대를 빼지 마세요.** 시간이 모자라면 그 시대의 **전용 소품을 줄입니다** — 공용 빌더
(`buildGround` `buildMountains` `scatterHouses` …)만으로도 지형은 성립하고, 퀘스트는 그대로
다 돌아갑니다. 빈 시대가 하나도 없는 편이 데모에서 훨씬 낫습니다.

**소품에 힘을 준다면 이 셋**: 삼국(영토 변화가 가장 잘 보임) · 조선 후기(생활사가 풍부) ·
광복과 6·25(미니게임이 가장 많음). 심사에서 이 셋을 먼저 보여 주세요.

## 2. 분업

세 사람이면 이렇게 나눕니다. **2단계가 끝난 시점부터 병렬**이 가능합니다.

```
      1단계 (다같이 또는 엔진 담당 혼자)
              │
      2단계 (엔진 담당: 미니게임 10형식)
              │
      3~4단계 (엔진 담당: 변환 규칙 → 12시대 일괄 변환)
              │
   ┌──────────┼──────────┐
 엔진 담당   소품 담당   지도 담당
 소품 4시대  소품 5시대  지도 모드 · 항목 20개
   └──────────┼──────────┘
              │
      7단계 (다같이 검증)
```

**시대 파일은 서로 독립이라 충돌하지 않습니다.** 단 `worlds-registry.js`는 모두가 건드리므로, 한 사람이 마지막에 몰아서 등록하는 편이 낫습니다.

## 3. 만드는 차례와 의존 관계

> 대회 규칙상 **지시문(프롬프트) 원문은 이 문서에 싣지 않습니다.**
> 시작 시각 이후에 직접 작성하세요. 여기에는 *무엇을 어떤 순서로,
> 무엇을 주의하며* 만들지만 적습니다.


### 1단계 — 껍데기와 엔진 뼈대 (1.5h)

엔진 파일들은 **서로를 참조하는 순환 구조**입니다. 쪼개서 만들면 어긋나니 한 번에 지시하세요.

*(지시문은 대회 시작 후 직접 작성)*

**검증**: 빈 월드 하나로 3D 씬이 뜨고 캐릭터가 움직이면 통과입니다.

---

### 2단계 — 미니게임 10형식 (1.5h)

*(지시문은 대회 시작 후 직접 작성)*

**검증**: 10형식을 임시 퀘스트에 하나씩 붙여 성공·실패 양쪽을 다 눌러 보세요.
바늘형은 **눈으로 구간 안일 때 눌러서 명중으로 처리되는지**를 꼭 확인하세요 — [12-BUILD-RULES.md](12-BUILD-RULES.md) §3.

### 3~5단계 — 시대 12개

**시대마다 프롬프트를 반복하지 마세요.** 콘텐츠 문서를 시대 파일로 옮기는 규칙을 한 번
만들어 12개에 그대로 돌립니다([12-BUILD-RULES.md](12-BUILD-RULES.md) §6). 그 뒤 시대별
전용 소품만 나눠 맡습니다 — 시대 파일은 서로 독립이라 여러 사람이 동시에 해도 충돌하지 않습니다.

*(지시문은 대회 시작 후 직접 작성)*

**검증**: 타임라인에서 그 시대로 들어가 `발견 0/N`이 뜨고, 퀘스트 하나를 완료하면 역사 가방에 담기는지.

## 4. 자주 막히는 지점

| 증상 | 원인 | 대응 |
|---|---|---|
| 탐험 모드가 빈 화면 | `vendor/three` 없음 | 07-ASSETS.md 1번부터 |
| `Unexpected token` | 배열 마지막 쉼표 누락 | 추가 지점 직전 줄 확인 |
| 고쳤는데 오류가 계속 보임 | 콘솔 기록이 남은 것 | **새 탭**에서 다시 판정 |
| 마커가 절반만 보임 | 좌표가 두 곳에 나뉨 | 출처를 한 파일로 못박기 |
| 한글 자판에서 WASD가 죽음 | `e.key` 로 받음 | `e.code` 로 받기 ([12-BUILD-RULES.md](12-BUILD-RULES.md) §2-3) |
| 옆으로 가면 화면이 빙글빙글 | 카메라 자동 추적 | 앞으로 갈 때만 추적 (§2-5) |
| 눌렀는데 빗나감 | `click` 으로 판정 | `pointerdown` 으로 (§3) |
| 도착하자마자 나무 속 | 산포 제외 목록에 `spawn` 없음 | (§4) |
| 음영기복이 사라짐 | `clipPath` 안의 `<g>` | 구조 바꾸기 |
| 조이스틱 좌우 반전 | `joy.x` 부호 | 부호 규칙은 [12-BUILD-RULES.md](12-BUILD-RULES.md) §2-2 표 하나로 통일 |

## Phase별 상세 로드맵

> 팀원 수연 님이 정리한 내용입니다. 위 1장의 시간 배분과 함께 보세요.

## Phase 0 — 뼈대 스캐폴딩 (0:00 ~ 0:30, 반드시 순차로 먼저)

**누구 한 명이(보통 엔진 담당) 혼자, 나머지는 대기 또는 에셋 확인**:

0. [`../MASTER.md`](../MASTER.md) 와 [`12-BUILD-RULES.md`](12-BUILD-RULES.md) 를 먼저 읽습니다 — 다른 문서와 어긋나는 곳은 MASTER, 그다음 12가 맞습니다.
1. 저장소 초기화, 폴더 구조 생성(§00-OVERVIEW §폴더 구조).
2. `index.html` 뼈대 작성 — 인트로 화면 + `#app`(지도모드 빈 컨테이너, §04-LEARN-MODE §2) + `#explore`(탐험모드 빈 컨테이너, §01-ARCHITECTURE §1) DOM을 전부 만들어 커밋. **이 단계에서 두 모드의 DOM id를 전부 확정**해야 이후 두 팀이 독립적으로 작업 가능.
3. `css/styles.css`에 `:root` 디자인 토큰(§03-DESIGN-SYSTEM §1)만 먼저 커밋.
4. `js/engine/state.js`, `constants.js`, `worlds-registry.js`(빈 `WORLDS={}`로 시작) 뼈대.
5. `js/asset-credits.js` 빈 배열로 생성.

이 단계가 끝나면 **세 사람이 완전히 병렬로** 작업 시작 가능.

## Phase 1 — 엔진 (엔진 담당, 0:30 ~ 2:00)

`01-ARCHITECTURE.md`를 위에서부터 그대로 구현:

1. `player.js`(아바타 빌드 + 이동/카메라 루프) — §7
2. `scene-helpers.js`(공용 3D 빌더) — [`03-DESIGN-SYSTEM.md`](03-DESIGN-SYSTEM.md) §3 목록 그대로
3. `markers.js`(마커 시스템) — §9. **시간이 없으면 `ICON_PARTS` 전체를 다 채우지 말고 `buildMarkerGem` 폴백만으로 시작** — 어차피 에러 없이 동작하고, 나중에 여유 있을 때 개별 아이콘을 추가해도 됨.
4. `minigames.js`(§02-MINIGAMES 10형식) + `grader.js` — 급하면 **기본형·`stack`·`blank`** 셋을 먼저 만들면 절반이 돌아갑니다(`blank` 16회 · `stack` 12회). 나머지는 콘텐츠 작업과 병행해 추가하되 **10형식 전부가 목표**입니다.
5. `ui.js`(퀘스트 모달/조사 패널/NPC 대화/가방/미니맵/시대완료) — §10
6. `boot.js`(부팅/입력 바인딩) — §2, §8

이 시점에서 `worlds-registry.js`에 **최소 1개 시대**(더미 데이터라도)를 등록해서 첫 진입부터 시대완료까지 한 바퀴 굴러가는지 확인하세요 — 엔진 버그를 이 단계에서 잡아야 이후 콘텐츠 작업이 안전합니다.

## Phase 2 — 콘텐츠 병렬 작업 (전원, 2:00 ~ 종료 1시간 전)

- 엔진 담당: 변환 규칙을 만들어 `content/*.md` **12개를 한꺼번에** `js/eras/*.js` 로 옮기고
  `worlds-registry.js` 에 전부 등록합니다([12-BUILD-RULES.md](12-BUILD-RULES.md) §6).
- 소품 담당: 시대를 나눠 맡아 **그 시대의 전용 3D 소품**을 채웁니다(퀘스트는 이미 들어가 있습니다).
- 지도 담당: 지도 모드 + **학습 항목 신규 20개**(후삼국 8 · 전쟁기 12) + 사진 + 인쇄 — [`../MASTER.md`](../MASTER.md) §4-4.
- 각 시대를 마무리할 때 체크리스트:
  1. 퀘스트·NPC·관문이 콘텐츠 문서 그대로 들어갔는지 (텍스트는 한 글자도 바꾸지 않습니다)
  2. `## 지역` 표의 `bg` `spawn` `bound` `loading` 을 그대로 옮겼는지
  3. 3D 월드 빌더 함수(`buildWorld*`/지역별 빌더) — §03-DESIGN-SYSTEM §3 공용 빌더를 조합해서 새로 작성 (콘텐츠 문서에 배치 좌표/규모 힌트가 있으면 참고)
  4. `worlds-registry.js`에 등록
  5. 브라우저에서 직접 플레이해서 퀘스트 하나 완료까지 확인

### 우선순위 (시간이 부족할 때)

**시대를 빼는 것은 마지막 수단입니다.** 콘텐츠 이전은 규칙 하나로 12개가 한꺼번에 되므로,
모자라는 것은 언제나 "그 시대의 3D 소품"이지 "그 시대" 자체가 아닙니다. 이 순서로 줄이세요.

1. 시대별 전용 소품 → 공용 빌더로 대체 (지붕 높이만 §12-BUILD-RULES §4 대로 확인)
2. 사진·GLB 모델 → 없어도 화면이 성립합니다
3. 그래도 모자라면 **한 시대 안에서 퀘스트 개수를 줄입니다** — `content/*.md` 의 퀘스트는
   서로 독립적이라 일부만 옮겨도 안전합니다
4. 정말 마지막에만, 시대를 `worlds-registry.js` 에서 뺍니다 (선택 화면에 안 보이게)

소품에 힘을 줄 순서: 삼국 · 조선 후기 · 6·25 → 고려 · 조선 전기 → 신석기 · 청동기 →
통일신라·발해 · 일제강점기 → 구석기 · 후삼국 · 개항기.

## Phase 3 — 통합/QA (마지막 1시간)

1. 인트로 → 지도모드 → 탐험모드 → 지도모드 왕복이 전부 되는지(§01-ARCHITECTURE §11 계약 지점 4개) 실제로 클릭해서 확인.
2. `localStorage` 초기화(시크릿 창) 후 처음부터 한 번 완주.
3. 모바일 뷰(개발자 도구 반응형)에서 터치 조이스틱/바텀시트 확인.
4. `js/asset-credits.js`에 실제로 쓴 에셋이 다 등록됐는지 확인.
5. README 또는 발표 자료에 "빈 화면/미완성 시대"가 없는지 최종 점검 — 시간이 부족해 못 채운 시대는 `worlds-registry.js`에서 아예 빼거나(선택 화면에 안 보이게), 최소 크래시는 안 나게.

## 병렬 작업 시 주의할 공유 파일

- `worlds-registry.js`: 여러 사람이 동시에 새 시대를 등록하며 자주 충돌 나는 파일. **엔진 담당이 병합을 전담**하거나, 각자 자기 시대 import/등록 줄만 추가하고 커밋 전에 항상 pull.
- `index.html`/`css/styles.css`: Phase 0 이후로는 거의 건드릴 일 없어야 정상. 정말 필요하면 자기 섹션에만 추가(§00-OVERVIEW §충돌 방지 규칙).
- `js/asset-credits.js`: 배열 끝에 추가만 하는 append-only 파일로 취급하면 충돌이 거의 안 남.
